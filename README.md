# 映格视频库

Windows 本地视频管理工具。支持文件夹扫描、缩略图、分类与标签、搜索、元数据搜刮、AI 辅助审核和内嵌网页。

1.5.1 整合版的功能与使用边界见[发布说明](RELEASE_NOTES_1.5.1.md)；原定阶段目标、`javdb-api` 功能对照与多平台评分规则见[版本方案](NEXT_VERSION_PLAN.md)。版本方案中的完整目标与下述已验证的实现范围应分别看待。

2026-10-25 的本机验收：Release 构建 0 警告、0 错误，567/567 项固定离线诊断通过。隐藏窗口中以 32,909 部真实索引视频滚动 300 秒、2,599 次，UI 片段 P95 为 48.9 毫秒、P99 为 71.3 毫秒，超过 100 毫秒的片段有 2 次且未连续发生；工作集峰值 578.8 MiB。源码构建、1.5.1 便携程序和独立 AppId 的隔离安装均读到当前 Windows 用户同一缓存的 13 个文件夹、32,909 部视频。C: 内置盘到 G: USB NVMe 的不同物理设备导入检查 21 项通过；保存的 1.5.0 程序后台原位更新至 1.5.1 并重启通过。正式 Inno Setup 7 包仅核对版本、SHA-256 和脚本，实际安装使用隔离克隆包；另一个 Windows 用户、另一台电脑和不可达来源尚未端到端验收。

1.5.1 为普通电影、剧集和动画增加 Wikidata 候选来源，为动画增加 Kitsu 与 Tenrai 候选来源，并增加 OMDb、Trakt 两个单部手动来源。新来源均默认关闭；启用后 Wikidata、Kitsu 和 Tenrai 可参与标题队列，OMDb 需要用户自己的 API Key，Trakt 需要用户自己的 Client ID，两者均不参加“全部来源”或后台全量队列。详情会重新核对作品身份，资料与平台评分先进入人工审核；Kitsu 缺少年份的条目会拒绝详情匹配。Tenrai 和 Trakt 目前仅通过固定样例验收，尚未在本机完成真实联网核对。推荐页可查看理由、减少类似推荐并分别关闭收藏、观看、分类、标签和在线主题信号。

## 安装

从 [Releases](https://github.com/PRC1978/YinggeVideoLibrary/releases) 下载 `YinggeVideoLibrary-Setup.exe`。安装程序为当前 Windows 用户安装，无须管理员权限。需要 Windows x64。

视频文件不会复制到安装目录。设置、索引和缩略图保存在用户目录下的 `.YinggeVideoLibrary`，升级或卸载安装程序不会自动删除这些数据。首次启动会尝试从旧版缓存导入。

软件可按设置的间隔在后台检查 GitHub 上的新版本，也可以在“设置 → 软件更新”中手动检查。发现新版时显示版本、发布说明以及取消、跳过此版本、立即更新；跳过后仍可手动查看。从 1.2.0 起，软件内更新下载独立 EXE，核对 GitHub Release 的 SHA-256 与文件大小，退出旧进程后原位替换并自动重启。安装目录需要当前用户可写；若 Release 缺少便携更新文件，软件会提示手动下载安装包。1.1.0 及更旧版本首次升级仍需运行一次安装程序。

1.5.1 的“设置”页按外观、视频库、搜刮、AI、播放、在线、启动、更新和数据分成可展开卡片，并可搜索设置主题。启动卡片可设置当前 Windows 用户登录后自启、最小化到系统托盘、开机自启后最小化、默认启动页，并可创建桌面快捷方式；手动打开时仍显示窗口，托盘双击恢复，右键退出。自动检查更新的开关与间隔、番号搜刮队列请求间隔、旧 JavDB 资料补全、分页卡片数、候选缓存占用与清理等选项均会保存或执行。清理缓存前会询问，不会删除已保存的影片资料或审核记录。

分类页与视频列表的选择栏可全选整个视频库，也可只选当前筛选结果或当前页；选择栏显示范围和已选数量。批量分类窗口支持搜索与虚拟滚动，可添加、替换、新建或清除分类。

1.5.1 支持先左键点击一张视频卡片或复选框、再按住 Shift 左键点击另一张，以当前筛选顺序连续选择，两端均包含且可跨页。分页模式可输入页码跳转。视频卡点“查看分类”会显示完整分类路径；点“查看标签”可查看、编辑或点击标签筛选；列表顶部“浏览标签”可搜索全库标签与数量。右键及卡片“更多”打开固定大小的操作菜单，分类改由按层级排列、可搜索且虚拟滚动的选择器打开。选中父分类后点“＋ 子分类并添加”可在其下创建子分类，同时把选中的视频加入该子分类；“＋ 子分类并替换”会先清除原分类。若要先创建空的子分类，在分类工作台选择父分类，点“＋ 在当前分类下新建子分类”。子分类仍可作为父分类，继续向下创建。
1.5.1 的“文件夹”页使用图形卡片按扫描根目录、子目录逐级浏览，可通过面包屑或返回按钮回到上级，并在当前层搜索和排序。目录树从视频索引后台建立，当前层分页显示目录与视频；没有索引视频的空目录不显示。
全库批量分类、标签、观看状态和收藏按段更新界面，并可撤销最近一次批量操作；文件保存放在后台。

## 构建

需要 .NET 9 SDK。生成单文件 Windows 程序：

```powershell
dotnet publish -c Release -r win-x64 --self-contained true /p:PublishSingleFile=true /p:IncludeNativeLibrariesForSelfExtract=true -o '..\发布'
```

使用 Inno Setup 7 的 `ISCC.exe` 编译 `YinggeVideoLibrary.iss`，安装包输出到 `..\安装包`。发布新版本时，同步更新 `.csproj` 和安装脚本中的版本号，创建对应的 `vX.Y.Z` GitHub Release，并同时上传 `YinggeVideoLibrary-Setup.exe` 和从发布目录复制的 `YinggeVideoLibrary-win-x64.exe`。两个文件名须保持稳定，供更新器识别。

## 数据与凭据

本地视频、索引和缩略图不属于源码仓库。TMDB Token、AI API Key 和可选的 Javinfo Key 保存在当前 Windows 用户的凭据管理器中；新版本启动时会迁移旧配置文件中的明文密钥，并清理配置备份。启用在线 AI 功能后，软件会把对应任务所需的标题等信息发送到用户自行配置的 API 服务；本地规则分类无需联网。本机 OpenAI 兼容接口可使用 `http://127.0.0.1:端口/v1` 且不需要密钥。

默认共用数据目录为当前 Windows 用户的 `%USERPROFILE%\.YinggeVideoLibrary`，磁盘缩略图在其 `thumbs` 子目录，搜刮候选缓存位于 `candidate-cache`。设置页的“资料库和缓存”会显示实际路径和占用，并可直接打开缩略图目录。已解码海报另有运行期间的内存缓存，没有磁盘地址：默认 128 MB，可选 64 MB 至 2 GB 或“无限制”。“无限制”只取消已载入海报的容量上限，不会在启动时解码全库，可能显著增加进程内存占用；退出程序会清空内存缓存，也不会改变磁盘目录或备份位置。

AI 请求按顺序限速并重试暂时性错误。每日费用上限由用户填写的输入、输出 Token 费率估算，实际费用以 API 服务商账单为准。搜刮候选在本机缓存三天；审核记录和历史保存在共享数据目录。确实无匹配或已取得完整详情但可信度低的结果会显示在视频卡片上，并自动打上可追踪的“素人”标签；网络错误或详情暂不可读不会被当作无匹配。

“搜刮”页可将全部符合条件、尚待搜刮的视频一次加入持久队列，不再限制每次 100 部。有番号的视频可查 JavDB，并以 JAVDatabase 补充；无番号或需要标题匹配时，可按启用情况查询 TMDB、TVmaze、Bangumi、JavDB、JAVDatabase 和 Pornhub 的公开候选。AniList 动画只供手动搜索。标题匹配得到的候选必须人工审核后才会写入视频资料。来源不可达、要求验证或页面无法识别时会保留错误状态，不会据此断言没有匹配。可预览范围，按文件夹及子文件夹、已看状态、标签、文件名关键词和最小大小跳过视频；这些条件也作用于已有的待处理任务。可暂停、继续、重试失败或取消全部待处理任务，取消时会保留已保存的资料和失败记录。队列在重启后保留，可在“搜刮”页继续轮询。大量任务会逐项限速请求，完成全部搜刮可能需要较长时间。队列变更逐项写入日志，并定期生成快照，减少大量任务时反复重写整个队列的开销。1.5.1 队列进一步按来源公平调度；429 只冷却对应来源且不耗尽单视频重试次数，401/403 显示为凭据或权限问题，供人工处理。完整资料搜刮会展示按匹配分数及来源权重排序的多个候选。审核页可按状态、来源和可信度筛选，队列每页显示 12 条，批量审批前显示预览，并提供可跨重启的多次人工审核撤销、完整历史及 CSV 导出。审核写入使用写前记录和同序文件锁，重启会恢复中断操作；外部程序绕过锁修改时停止恢复并保留记录。

映格内置的免费搜刮会自行查询启用的公开来源，无需 Javinfo。1.5.1 对明确番号分别读取 JavDB 和 JAVDatabase 详情，逐站核对番号后聚合字段、原值与来源；来源之间的身份字段有差异时转人工审核，不能据此覆盖已人工确认的资料。某站不可用只影响该站，不能当作全网无结果。Javinfo 保留为单独启用的付费备选来源，需要用户自己提供 API Key；它只出现在手动搜刮来源中，不进入“全部来源”或后台全量队列。Javinfo 门禁还要求明确番号和日文原名经用户核对后才能请求，返回的番号及日文原名仍会再次核对。默认每日最多尝试 50 次请求，请求间隔至少 13 秒，用量记录保存在共享数据目录。搜索候选和选中后读取详情各算一次尝试；实际收费与余额以 Javinfo 账单为准。

“搜刮 → JavDB 作品关系浏览”可手动查找一个作品，再从该作品详情实际提供的演员、系列、标签链接浏览相关候选。1.5.1 还可按演员姓名直接搜索公开演员卡，选中后分页浏览作品；最多选择三个公开标签，分别读取有限页后在本机求交。选择候选并指定本地视频后，会读取详情、核对番号并放入人工审核；通过前不修改视频资料。关系页无法识别、来源限流或要求登录时会报告读取失败，不推断该关系下没有作品，也不要求或导入登录 Cookie。

1.5.1 的跨来源关系预览可在 JavDB 与 JAVDatabase 各选一条经过详情核实的演员、系列或标签关系，每站最多读取前三页，再按明确番号在本机求交；候选送审前仍须核对作品详情。设置页也可[导入自己导出的站点收藏清单](SITE_LIST_IMPORT.md)：先预览 CSV/JSON 的匹配和重复项，独立保存清单；确认已匹配条目后，才手动预览并应用本地收藏或标签，操作记录可撤销。两项功能已有固定离线样例，真实站点及实际导出文件仍须验收。

从 1.4.0 起，队列使用新日志格式；同一电脑上若仍保留旧版程序，请将各副本都更新到 1.4.0，以免旧版看不到新队列的后续变化。

可选的“目录人物提示”会检查视频所在目录直到已添加的视频库根目录，综合目录层级和名称特征区分人物、作品与普通分类，不限制最近两层。文件名有可搜索标题时优先使用文件名；若只有 `1.mp4`、`Video_0001.mp4` 这类编号，且能辨认人物目录及其下方的作品目录，则用作品目录名作为标题。首轮标题候选不足或匹配较弱时，最多附加一个人物名再查询；不会把盘符或完整路径发送给来源。人物名与候选演员相符可作为加分证据，但不能仅凭目录名自动批准弱标题候选；关闭此选项后不使用目录提示。

“完整资料搜刮”会在选定候选后读取来源公开的详情字段（如日期、时长、演员、导演、类别和简介），并把详情随候选传入审核及保存。视频卡右键和审核队列“资料”按钮可查看每个字段的来源及读取阶段；缺失字段显示“来源未提供”，旧记录明确显示未逐项记录来源。旧版已保存的摘要可在设置中允许后台重新搜刮补齐 JavDB 详情；补全失败不会覆盖已审核资料。TMDB 和 TVmaze 使用官方详情接口；JavDB 读取其公开详情页，站点或地区限制可能让详情不可用，届时不会把搜索摘要当作完整资料自动通过。1.5.1 对同一番号的 JavDB 与 JAVDatabase 核实详情实行内置聚合，保留跨来源原值和冲突证据；其他来源仍按各自身份核对和人工审批规则处理。JAVDatabase 已能在核对番号后读取公开剧照和预告链接，保存各字段来源；链接只在用户点击时打开，不由搜刮程序下载或播放。逐字段审核可保留原值、采用候选、采用指定来源值或清空。

1.5.1 新增左侧“人物”入口；也可从设置或单部视频的完整资料打开人物与角色档案。可手工填写姓名、别名、生日、身份、身高、体重、血型、生平和本地肖像，并明确选择本地作品关联。已核实的 JavDB 演员链接、TMDB 或 TVmaze 人物编号可从对应作品建立来源身份；角色名、作品证据与手工资料分开显示。同名人物不会自动合并。只有用户点击来源详情时才读取该人物的公开资料与允许的肖像；缺失的生平等字段留空，不覆盖手工填写。关联作品每页显示 40 部，全部关联会随备份、选择性导入和跨设备重定位保存。

视频“资料”窗口可保存独立的个人 0–10 分评分。平台原始评分、票数、来源和匹配证据单独显示；至少两个身份已核对且分制明确的独立平台才计算综合分。JavDB 只有裸分数但没有可核对分制时，原文保留展示，不参与综合计算。已审核的作品可按番号尝试 JavDB 与 JAVDatabase 评分，也可手动选择 Bangumi、AniList 和已配置 Token 的 TMDB 候选，确认同一作品后只保存评分，不覆盖已审核的其他资料。个人评分保存在共享数据目录的 `personal-ratings.json`。1.5.1 可在“设置 → 一致性备份”安排下次启动时离线备份；软件退出后取得数据目录独占使用权，再打包并校验资料、评分、队列、AI 作业与审核及图形分类撤销历史。设置页的“立即备份”会排定这次离线备份，需关闭全部窗口后重新启动才会执行。Windows 凭据中的 API Key 不进入备份；AI 请求虽随包保存为当前账户加密密文，换 Windows 用户或电脑后不能重试，须重新创建作业。

1.5.1 在“设置 → 数据与备份”还可启用每天、每周或每月的定期一致性备份；默认保留最近 3 轮自动备份，也可设置 1–30 轮及备份位置。到期时会标为待执行，关闭所有软件窗口并再次启动后，在加载视频库前执行。自定义位置下使用本视频库的专用子目录；轮换只清理已校验的自动备份包，手动备份、旧版包和目标文件夹中的其他文件会保留。备份位置与统一视频库数据目录分别设置，不会迁移正在使用的索引和资料。目标盘不可用时待办保留，设置页显示失败原因。

重复视频检测先比较同样大小的视频，再在后台计算完整 SHA-256；可搜索、分页查看重复组，并预览保留项的分类、标签和个人评分变化。用户确认前重新核对文件及资料；确认后只合并本地资料，保留可跨重启撤销的历史，不删除或改写视频文件。保存的智能筛选器在搜索框右键菜单中管理。文件夹变动由监听器增量更新共享索引。球形分类图保留图中每个分类及相关标签节点的连线；所选标签会连接其涉及的全部分类，次级标签只按同一视频中的真实共现画线。节点共用一个绘图画布，密集时只显示部分文字，仍可通过搜索导航访问其余节点。分类数据没有变化时不重复构建图索引。

“推荐”页在本机根据收藏、观看状态、标签、分类和时间排序视频，显示推荐理由并可换一批。1.5.1 推荐卡每批只加载当前可见视频的封面或缩略图，可点“图片”放大，点“视频预览”在独立窗口按需播放，也保留外部播放器入口。卡片优先显示人工填写或已核实的番名，其次是文件名和可辨认的作品目录名；只有编号又没有可靠名称时显示“片名待补充”，编号仍可在次要位置查看。点“编辑番名”可保存本地显示名，随时恢复自动名称，不改写已审核的搜刮资料。某些格式若无法由 Windows 预览组件解码，可使用卡片上的播放器入口。在线部分根据本地收藏和观看行为选择通用的哔哩哔哩主题关键词；点击主题后才打开该关键词的搜索页，不发送本地视频文件名、路径或自定义标签。它是主题搜索入口，不是哔哩哔哩账号的个性化推荐接口。

“在线”页可尝试将本机已解压的小电视空降助手扩展加载到 WebView2；可自动查找 Edge 中该扩展的文件夹，也可手动选择直接包含 `manifest.json` 的目录。WebView2 与 Edge 使用独立的登录状态和扩展设置；实际效果取决于本机 WebView2 运行环境、扩展版本和站点页面，启用后需刷新哔哩哔哩。此功能不直接安装 Edge 商店扩展，也不保证扩展的全部功能在内嵌浏览器中可用。
