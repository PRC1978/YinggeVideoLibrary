## 一、索引保存判定（本轮主要修复）

`SaveIndexAsync` 在 `PreservedMismatchedIndex=true` 时返回成功但没有写入新索引；「没有配置文件夹」的早退分支同样没有写入。清理、撤销、中断恢复原先只捕获异常，会把这两种情况当成功。

修改：

- `IndexSaveResult` 增加 `Written` 字段。保护分支返回 `Written=false`，真正落盘返回 `true`，无文件夹早退返回 `false`。
- 清理 / 撤销 / 中断恢复的索引回调改为 `return saved.Written`，并在保护分支给出专门文案（「当前文件夹设置与磁盘上的旧索引不一致，程序保护了旧索引」）。
- 顺序保持不变：日志写成功后才改索引；完成标记只在索引确实写入后提交。

新增故障测试（`--self-test-missing-files`，**30/30**）：

| 断言 | 覆盖点 |
| --- | --- |
| `mismatchedIndexIsNotReportedAsWritten` | 保护分支 `Written=false` 且磁盘仍是旧索引 |
| `matchingFolderSetIsWritten` | 同一路径、文件夹一致时正常写入 |
| `cleanupFailsWhenIndexIsProtected` | 清理被拒、日志回滚（无 pending、不可撤销）、磁盘不变 |
| `protectedIndexStaysConsistentAfterRestart` | 再次启动重复清理仍被拒，日志无 completed 记录 |
| `cleanupWritesWhenFolderSetMatches` | 对照组：文件夹一致时清理写入并生成可撤销记录 |

说明：`Written` 的判定在 `WriteIndexSnapshotAtPath` 的真实实现上验证，不是打桩。清理流程中的「内存列表」由回调返回 `false` 后回滚（`foreach (var item in removed) videos.Add(item)`），该分支未单独做 UI 断言，见第五节。

## 四、侧栏可达性（发现并修复一处真实问题）

800×550 下用真实滚轮滚到侧栏底部，修复前只能看到「推荐/分类/文件夹/状态/人物/搜刮」，**「在线」不可达**。原因是 `ScrollViewer` 设了 `CanContentScroll="True"`，而内容是不实现 `IScrollInfo` 的 `StackPanel`，滚动被按整块处理。

改为 `CanContentScroll="False"`（物理滚动）后，同样操作可见「分类/文件夹/状态/人物/搜刮/在线」，齿轮设置固定在底部。

证据：`shots/sidebar-800-wheel-zoom.png`（修复前，缺「在线」）、`shots/sidebar-800-wheel2-zoom.png`（修复后含「在线」）。
