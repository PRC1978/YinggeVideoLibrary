# 分类图旋转帧量测（2026-11-07）

## 方法修正

旧版 `--diagnose-ui-startup ... --categories` 在设置 `Rotation` 后对同一个 WPF 控件调用 `InvalidateVisual` 和 `RenderTargetBitmap.Render`。`InvalidateVisual` 的重绘是延迟执行的；实测逐帧计时期间 `OnRender` 没有运行。因此旧报告的“旋转帧”数字不能作为实际重绘成本。本轮诊断改为每帧新建 `DrawingVisual`，调用同一 `OnRender` 路径，再绘制到位图；旋转预览 PNG 也走该路径。

诊断仅使用 `%TEMP%/yingge-graph-171` 中的 600 部合成视频。该配置生成 796 个节点，导航 34 页均可访问；没有读取真实视频库。记录了完整 1120×620 画布和实际 708×372 视口两种尺寸。以下是离屏软件渲染计时，不能直接当作真实窗口帧率或不同电脑上的结果。

## 结果

| 项目 | 观察值 |
| --- | ---: |
| 完整画布旋转帧平均 | 约 41 ms |
| 实际视口尺寸平均 | 约 30–41 ms（运行波动） |
| 同尺寸空画布 | 约 0.1 ms |
| `OnRender` 提交图形指令 | 约 4.7–5.5 ms |
| 其中节点投影 / 层级线与节点 / 标签 | 约 0.3 / 0.9–1.0 / 2.4–2.8 ms |

在同一诊断内暂时隐藏单层以定位成本：去连线约 23–24 ms，去节点约 14–17 ms，去标签约 29–31 ms。各层共享像素和框架开销，差值不能相加；节点圆点是明显的主要成本。

尝试把所有圆点合为三个 `StreamGeometry` 批绘，实际视口计时约 35.4 ms，对照逐个绘制约 30.4 ms。没有稳定改善，产品绘制路径已恢复原样。诊断中的临时隐藏开关默认全部关闭，不改变用户界面，也没有减少节点、连线或标签。

另测节点描边：全部去描边约 20.8 ms、半径不大于 3.5 的小节点去描边约 24.8 ms、全部描边约 32.7 ms（同一次运行、各 12 帧）。保留大节点描边，在“流畅优先”模式的三维旋转画面中省略小节点描边；静止图、其他动画模式、节点填充、命中区域、连线和文字不变。`rotated.png` 与 `smooth.png` 逐图目检，小节点略显饱满，结构和标签一致。该结果是离屏软件渲染改善，真实窗口交互收益仍需单独验证。

最终构建 0 警告、0 错误。最终分类图诊断退出码 0：796 节点、226 条所选标签关联线、34 页导航完整。最终同进程对照为小节点无描边 25.3 ms、全部描边 34.1 ms；完整画布仍全部描边，以供回归比较。`--self-test-features` 通过，`realLibraryRead=false`。证据在 `%TEMP%/yingge-graph-171-accepted.json`、`%TEMP%/yingge-graph-171-features.json` 及同名前缀的图像。

## 后续判断

当前更有价值的是对真实窗口的交互延迟做采样，特别是在 60 张视频卡片异步填充时。此夹具中该阶段输入/旋转反馈出现约 70–104 ms 的平均值，明显高于单纯投影的 0.3 ms。下一轮应把图的输入响应与卡片加载并行度分开测量，再决定是否改卡片调度。真实媒体海报和磁盘读取不在本夹具内。
