# 本地存储现状与关系型数据库评估

当前视频库不是 SQLite 等关系型数据库。主索引、资料和配置分别写入 `library-index.json`、`metadata.json`、`config.json`；队列、审核历史与人物档案另有各自的本地文件。工程没有 SQLite 包引用。

3 万部隔离合成库中，`library-index.json` 约 7.6 MB，`metadata.json` 约 14.1 MB，`config.json` 约 4.4 MB。这个规模下完整读写 JSON 的成本和跨文件一致性值得优化，但不能仅凭文件大小断定 SQLite 会使所有页面更快。

建议下一步做**可回退的 SQLite 迁移**：视频、扫描根、作品资料、人物、分类、标签和关系单独建表，以稳定视频 ID 建外键；队列与审核事务采用同库事务；搜索先以现有查询为对照，再评估 FTS5。保留旧 JSON 只读导入与完整备份，在隔离副本上验证 3 万部迁移、撤销、断电中断恢复、降级及结果逐项一致后才切换默认读写路径。WAL 的并发优势和备份文件生命周期需按 SQLite 官方文档单独验收，不应直接打开就替换现有保存机制。
