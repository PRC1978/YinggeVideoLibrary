# 本机 PostgreSQL 迁移状态

用户确定本机视频库使用 PostgreSQL。云端账号也使用 PostgreSQL，但属于另一台服务器上的另一套数据库，不会同步本机媒体资料。此分支 `codex/postgresql-local` 与 UI 分支分开。

## 本阶段已完成

- 引入 Npgsql 10.0.3；可在独立进程连接本机 PostgreSQL。
- 新增显式、只读源文件的事务导入：`library-index.json` → `library_video` / `library_folder`，`metadata.json` → `library_metadata`。视频 ID 沿用现有路径 SHA-256 前 24 位规则。导入标记保存两个原文件的 SHA-256。
- 目标库已有导入标记或数据时拒绝覆盖；导入前校验资料格式版本，导入持有事务级 advisory lock。任一写入失败会回滚整个事务。旧 JSON 保留不动。
- `--self-test-postgres <隔离库目录> <结果 JSON>` 通过 `YINGGE_POSTGRES_TEST_CONNECTION` 指向隔离测试数据库，验证数量、逐字段内容、源文件哈希及重复导入拒绝。

## 当前边界

**这还不是应用正式切换数据库。** 界面、审核事务、备份和其他数据文件目前仍按原有 JSON 路径运行。不可在设置中宣称 PostgreSQL 已启用，也不可删除旧 JSON。普通启动不连接 PostgreSQL，避免当前用户在未安装服务时打不开应用。

## 接下来必须完成

1. 按保存入口逐个引入数据库读写：视频索引、作品资料、分类和标签、审核记录和历史、人物档案、评分，再处理配置及队列。写入必须带版本号或条件更新，不能以旧内存快照覆盖新数据。
2. 审核通过/否决、撤销、清理缺失记录、备份恢复跨表事务化；保持“日志不能领先于数据”的现有安全要求。
3. 在设置中增加本机 PostgreSQL 初始化和迁移预览。连接凭据存 Windows 凭据管理器，不写入 `config.json`、日志或包。首次切换前生成可恢复备份；导入后逐项核对，失败保持 JSON 模式。
4. 确定 PostgreSQL 的本机安装与升级方案。服务仅监听 `127.0.0.1`，使用独立非超级用户角色；运行状态、端口冲突、磁盘空间不足和数据库损坏要有明确恢复界面。离线使用不能依赖云端账号服务。
5. 备份包包含数据库一致性快照；验证 3 万部库的导入、搜索、滚动、分类图、审核和备份恢复。跨旧版降级只能通过备份恢复，不静默改写旧 JSON。

## 已实测隔离样本

2026-11-04，在工作树内的临时 PostgreSQL 18.6、仅监听 `127.0.0.1:55432`：

- 1 部视频、1 条资料、1 个文件夹：导入和完整回读通过；重复导入被拒；源文件 SHA-256 未变。
- 3000 部视频（含标记缺失）/ 100 条资料 / 10 个文件夹：导入和逐项回读通过；进程总耗时约 3.7 秒；源文件未变。
- Release 构建 0 警告、0 错误。

测试集群和测试库均位于本工作树的 `artifacts/postgres-test`；没有读取或修改真实视频库。
