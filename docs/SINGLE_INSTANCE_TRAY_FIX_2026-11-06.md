# PostgreSQL 库占用与托盘窗口恢复

## 现象和根因

用户只看到一个映格窗口，再启动却收到 `.postgres-cluster-owner.lock` 被其他进程使用。只读 Restart Manager 探针确认：占用真实库锁的是已安装的映格进程 PID 77168，路径为 `D:\Downloads\YinggeVideoLibrary\映格视频库.exe`。它的主窗口已隐藏到系统托盘，所以任务栏中看不到第二个窗口。没有删除锁文件，也没有终止该进程。

## 修复

- 正常启动时先按规范化视频库目录寻找现有实例；找到后唤回原窗口并退出新进程，不再启动第二套数据库。
- 托盘隐藏的 WPF 窗口可能没有可用的 HWND，因此用当前用户专属的命名管道传递唤回请求。数据库和资料库租约仍负责阻止并发写入。
- 若现有实例启动较慢，在数据库租约冲突时再尝试一次；其他启动错误继续显示原错误，不能被误当作“已经打开”。
- 旧版本不支持唤回协议时，锁冲突提示明确告知去系统托盘寻找映格，且不要删除锁文件。

## 验证

- Release 构建：0 警告、0 错误。
- 隔离 PostgreSQL 视频库双启动：第一实例缩到托盘；第二实例退出码 0；第一实例重新显示。原始结果：`artifacts/single-instance/pg-final2.json`，`passed=true`。
- 仅停止本次隔离测试的数据库服务；正式安装程序和真实视频库未被修改。
- 完整数据库自检曾误启动两份使用同一输出路径的探针，未得到有效结果，已按精确路径清理这两份探针及其临时数据库服务；不把该次运行计为通过。

这项修复尚未安装或发布。已安装的旧版本在升级前仍需从托盘双击图标恢复窗口，或从托盘菜单完整退出后再启动。
