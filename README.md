# 映格视频库

Windows 本地视频管理工具。支持文件夹扫描、缩略图、分类与标签、搜索、元数据搜刮、AI 辅助审核和内嵌网页。

1.6.0 整合版的交付范围、分阶段验收、`javdb-api` 功能对照与多平台评分规则见 [下一版本方案](NEXT_VERSION_PLAN.md)。1.5.0 已发布；计划中的 1.6.0 功能以完成验收后的发布包为准。

## 安装

从 [Releases](https://github.com/PRC1978/YinggeVideoLibrary/releases) 下载 `YinggeVideoLibrary-Setup.exe`。安装程序为当前 Windows 用户安装，无须管理员权限。需要 Windows x64。

视频文件不会复制到安装目录。设置、索引和缩略图保存在用户目录下的 `.YinggeVideoLibrary`，升级或卸载安装程序不会自动删除这些数据。首次启动会尝试从旧版缓存导入。

软件可按设置的间隔在后台检查 GitHub 上的新版本，也可以在“设置 → 软件更新”中手动检查。从 1.2.0 起，更新优先下载独立 EXE，核对 GitHub Release 的 SHA-256 与文件大小，退出旧进程后原位替换并自动重启。安装目录需要当前用户可写；若 Release 只有安装包，才会启动安装程序。1.1.0 及更旧版本首次升级仍需运行一次安装程序。

“设置”页按外观、视频库、搜刮、AI、播放、在线、启动、更新和数据分成可展开卡片，并可搜索设置主题。自动检查更新的开关与间隔、番号搜刮队列请求间隔、旧 JavDB 资料补全、分页卡片数、候选缓存占用与清理等选项均会保存或执行。清理缓存前会询问，不会删除已保存的影片资料或审核记录。

分类页与视频列表的选择栏可全选整个视频库，也可只选当前筛选结果或当前页；选择栏显示范围和已选数量。批量分类窗口支持搜索与虚拟滚动，可添加、替换、新建或清除分类。
全库批量分类、标签、观看状态和收藏按段更新界面，并可撤销最近一次批量操作；文件保存放在后台。

## 构建

需要 .NET 9 SDK。生成单文件 Windows 程序：

```powershell
dotnet publish -c Release -r win-x64 --self-contained true /p:PublishSingleFile=true /p:IncludeNativeLibrariesForSelfExtract=true -o '..\发布'
```

使用 Inno Setup 7 的 `ISCC.exe` 编译 `YinggeVideoLibrary.iss`，安装包输出到 `..\安装包`。发布新版本时，同步更新 `.csproj` 和安装脚本中的版本号，创建对应的 `vX.Y.Z` GitHub Release，并同时上传 `YinggeVideoLibrary-Setup.exe` 和从发布目录复制的 `YinggeVideoLibrary-win-x64.exe`。两个文件名须保持稳定，供更新器识别。

## 数据与凭据

本地视频、索引和缩略图不属于源码仓库。TMDB Token、AI API Key 和可选的 Javinfo Key 保存在当前 Windows 用户的凭据管理器中；新版本启动时会迁移旧配置文件中的明文密钥，并清理配置备份。启用在线 AI 功能后，软件会把对应任务所需的标题等信息发送到用户自行配置的 API 服务；本地规则分类无需联网。本机 OpenAI 兼容接口可使用 `http://127.0.0.1:端口/v1` 且不需要密钥。

AI 请求按顺序限速并重试暂时性错误。每日费用上限由用户填写的输入、输出 Token 费率估算，实际费用以 API 服务商账单为准。搜刮候选在本机缓存三天；审核记录和历史保存在共享数据目录。确实无匹配或已取得完整详情但可信度低的结果会显示在视频卡片上，并自动打上可追踪的“素人”标签；网络错误或详情暂不可读不会被当作无匹配。

“搜刮”页可将全部符合条件、尚待搜刮的视频一次加入持久队列，不再限制每次 100 部。有番号的视频可查 JavDB，并以 JAVDatabase 补充；无番号或需要标题匹配时，可按启用情况查询 TMDB、TVmaze、Bangumi、JavDB、JAVDatabase 和 Pornhub 的公开候选。AniList 动画只供手动搜索。标题匹配得到的候选必须人工审核后才会写入视频资料。来源不可达、要求验证或页面无法识别时会保留错误状态，不会据此断言没有匹配。可预览范围，按文件夹及子文件夹、已看状态、标签、文件名关键词和最小大小跳过视频；这些条件也作用于已有的待处理任务。可暂停、继续、重试失败或取消全部待处理任务，取消时会保留已保存的资料和失败记录。队列在重启后保留，可在“搜刮”页继续轮询。大量任务会逐项限速请求，完成全部搜刮可能需要较长时间。队列变更逐项写入日志，并定期生成快照，减少大量任务时反复重写整个队列的开销。完整资料搜刮会展示按匹配分数及来源权重排序的多个候选。审核页可按状态、来源和可信度筛选，队列每页显示 12 条，批量审批前显示预览，并提供最近一次人工审核撤销、完整历史及 CSV 导出。

Javinfo 是单独启用的付费聚合来源，需要用户自己提供 API Key。它只出现在手动搜刮来源中，不进入“全部来源”或后台全量队列；默认每日最多尝试 50 次请求，请求间隔至少 13 秒，用量记录保存在共享数据目录。搜索候选和选中后读取详情各算一次尝试；实际收费与余额以 Javinfo 账单为准。软件直接使用 Javinfo 官方 REST 接口，不依赖 GitHub 上的 `javdb-api` MCP 项目或 Python 包。

“搜刮 → JavDB 作品关系浏览”可手动查找一个作品，再从该作品详情实际提供的演员、系列、标签链接浏览相关候选。选择候选并指定本地视频后，会读取详情并放入人工审核；通过前不修改视频资料。关系页无法识别、来源限流或要求验证时会报告读取失败，不推断该关系下没有作品。当前仅沿详情提供的链接浏览，不支持 JavDB 登录清单导入。

从 1.4.0 起，队列使用新日志格式；同一电脑上若仍保留旧版程序，请将各副本都更新到 1.4.0，以免旧版看不到新队列的后续变化。

可选的“目录人物提示”会检查视频所在目录直到已添加的视频库根目录，综合目录层级和名称特征区分人物、作品与普通分类，不限制最近两层。文件名有可搜索标题时优先使用文件名；若只有 `1.mp4`、`Video_0001.mp4` 这类编号，且能辨认人物目录及其下方的作品目录，则用作品目录名作为标题。首轮标题候选不足或匹配较弱时，最多附加一个人物名再查询；不会把盘符或完整路径发送给来源。人物名与候选演员相符可作为加分证据，但不能仅凭目录名自动批准弱标题候选；关闭此选项后不使用目录提示。

“完整资料搜刮”会在选定候选后读取来源公开的详情字段（如日期、时长、演员、导演、类别和简介），并把详情随候选传入审核及保存。视频卡右键和审核队列“资料”按钮可查看每个字段的来源及读取阶段；缺失字段显示“来源未提供”，旧记录明确显示未逐项记录来源。旧版已保存的摘要可在设置中允许后台重新搜刮补齐 JavDB 详情；补全失败不会覆盖已审核资料。TMDB 和 TVmaze 使用官方详情接口；JavDB 读取其公开详情页，站点或地区限制可能让详情不可用，届时不会把搜索摘要当作完整资料自动通过。当前不跨多个站点拼接字段，也没有单字段人工锁定。

视频“资料”窗口可保存独立的个人 0–10 分评分。平台原始评分、票数、来源和匹配证据单独显示；至少两个身份已核对且分制明确的独立平台才计算综合分。JavDB 只有裸分数但没有可核对分制时，原文保留展示，不参与综合计算。已审核的作品可按番号尝试 JavDB 与 JAVDatabase 评分，也可手动选择 Bangumi、AniList 和已配置 Token 的 TMDB 候选，确认同一作品后只保存评分，不覆盖已审核的其他资料。个人评分保存在共享数据目录的 `personal-ratings.json`；“立即备份数据”也包含个人评分和审核历史。

重复视频检测只比较同样大小的视频，再在后台计算完整 SHA-256；不会自动删除文件。保存的智能筛选器在搜索框右键菜单中管理。文件夹变动由监听器增量更新共享索引。球形分类图保留图中每个分类及相关标签节点的连线；所选标签会连接其涉及的全部分类，次级标签只按同一视频中的真实共现画线。节点共用一个绘图画布，密集时只显示部分文字，仍可通过搜索导航访问其余节点。分类数据没有变化时不重复构建图索引。

“推荐”页在本机根据收藏、观看状态、标签、分类和时间排序视频，显示推荐理由并可换一批。在线部分根据本地收藏和观看行为选择通用的哔哩哔哩主题关键词；点击主题后才打开该关键词的搜索页，不发送本地视频文件名、路径或自定义标签。它是主题搜索入口，不是哔哩哔哩账号的个性化推荐接口。

“在线”页可尝试将本机已解压的小电视空降助手扩展加载到 WebView2；可自动查找 Edge 中该扩展的文件夹，也可手动选择直接包含 `manifest.json` 的目录。WebView2 与 Edge 使用独立的登录状态和扩展设置；实际效果取决于本机 WebView2 运行环境、扩展版本和站点页面，启用后需刷新哔哩哔哩。此功能不直接安装 Edge 商店扩展，也不保证扩展的全部功能在内嵌浏览器中可用。

本仓库暂未附带开源许可证；公开源码不代表自动授予再分发或修改许可。
