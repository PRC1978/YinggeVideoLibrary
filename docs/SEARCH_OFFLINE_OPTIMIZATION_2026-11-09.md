# 搜索与完整列表离线复核（2026-11-09）

本轮只改源代码和离线验收记录，不安装、不发布，也不操控可见桌面。版本仍为 1.7.3.3；下列结果不能代替真实窗口的交互帧率或用户真实媒体库验收。

## 改动

- 搜索条件每次请求只解析一次；单关键词使用等价的快捷匹配路径。
- 搜索用的视频快照按对象复用，每次复用前核对标题、编号、状态、收藏、标签和分类等字段。后台线程仍只读取快照，避免与界面编辑争用；在隔离样本中编辑标题后能搜到新值，恢复后不能搜到该值。
- 完整虚拟列表在搜索结果的对象顺序与列数未变时保留现有数据绑定，避免 WPF 抛弃并重新生成可见卡片。结果确实变化时仍重建列表，不删除任何卡片或筛选能力。

## 证据与数值

输入是隔离的 33,038 条元数据逻辑副本和 400 张缓存海报；不打开原视频文件。离屏 WPF 测试不调用 `Show`，不创建真实窗口，不注入鼠标或键盘。每组运行两轮，各查询重复三次。下表为两轮的总耗时中位数范围和调度脉冲 P95 范围，单位毫秒。旧版和新版结果数均为 0 / 3,969 / 33,038。

| 查询 | 旧版总耗时 P50 | 本轮总耗时 P50 | 旧版脉冲 P95 | 本轮脉冲 P95 |
| --- | ---: | ---: | ---: | ---: |
| 零命中 | 244–252 | 212–215 | 32–44 | 33–45 |
| 已有标签 | 290–300 | 43–46 | 110–134 | 130–134 |
| 宽泛标题 | 385 | 199–208 | 92–97 | 48 |

标签查询总耗时改善主要来自**第二、第三次相同结果的复用**。第一次从其他结果集切到标签结果，仍有约 130–134 ms 的最长脉冲；宽泛标题的首次变化约 97–110 ms。由此不能宣称“所有搜索场景流畅”或已达到单次停顿 33 ms 门槛。首次结果变化时的虚拟列表重绑仍需单独优化和真实窗口验证。
