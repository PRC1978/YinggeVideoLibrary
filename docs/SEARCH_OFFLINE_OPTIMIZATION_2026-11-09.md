# 搜索与完整列表离线复核（2026-11-09）

本轮只改源代码和离线验收记录，不安装、不发布，也不操控可见桌面。版本仍为 1.7.3.3；下列结果不能代替真实窗口的交互帧率或用户真实媒体库验收。

## 改动

- 搜索条件每次请求只解析一次；单关键词使用等价的快捷匹配路径。
- 搜索用的视频快照按对象复用，每次复用前核对标题、编号、状态、收藏、标签和分类等字段。后台线程仍只读取快照，避免与界面编辑争用；在隔离样本中编辑标题后能搜到新值，恢复后不能搜到该值。
- 完整虚拟列表在搜索结果的对象顺序与列数未变时保留现有数据绑定，避免 WPF 抛弃并重新生成可见卡片。结果确实变化时仍重建列表，不删除任何卡片或筛选能力。

## 首次切换停顿的后续定位

在同一离屏夹具中启用现有 `RecycledCardRow` 计时后，首次从零结果进入标签结果创建了 3 行、15 张卡片：绑定合计约 45 ms，测量合计约 58 ms，排列约 22 ms；相同结果再次搜索时没有创建或重绑卡片。报告：`artifacts/1733-p0/perf-real/probe-row-diagnostic.json`。这将停顿定位在首次可见卡片生成与 WPF 布局，而不是前置筛选（约 0.5 ms）或结果应用（约 1.5 ms）。

尝试将虚拟列表屏外预建长度从 0.5 改为 0，两轮离屏对照中首次创建降为 2 行、10 张卡片，标签首次脉冲仍为 116–122 ms，而 90 次滚动布局的 P95 从约 3.6 ms 升至 15.4–15.7 ms。因此**已撤回这一试验改动**，保留原有滚动缓存。原始报告：`artifacts/1733-p0/perf-real/probe-cache0-{1,2}.json`。后续需在不牺牲滚动的前提下分帧生成卡片或降低卡片模板的首次绑定成本，并再次验证实际窗口体验。

## 完整列表的空结果修复

离屏检查发现，完整列表搜索零命中时，空结果面板虽然设为可见，其父滚动容器却被隐藏，页面因此一片空白。现让零命中进入已有空结果布局；选择范围也只在完整列表真正显示时读取虚拟行，避免把暂存的旧卡片误当作当前结果。隔离夹具验证零命中时完整列表隐藏、空结果容器和面板可见、可选择条目为 0；证据在 `artifacts/1733-p0/perf-real/probe-empty-state-verified.json`。两轮离屏性能对照的滚动 P95 为 3.6–3.8 ms，首次标签结果脉冲约 115–120 ms，未据此宣称首次卡片显示卡顿已解决。

修复后的 Release 构建为 0 警告、0 错误；完整功能自检 `passed=true`、`realLibraryRead=false`，记录在 `artifacts/1733-p0/perf-real/features-empty-state-correct.json`。离屏页面矩阵复测 10 主题 × 3 个尺寸 × 8 页面，共 240 个布局、1,804 项检查，失败 0 项；记录在 `artifacts/1733-p0/perf-real/ui-empty-state-final/report.json`。这些检查不等于真实前台窗口验收。
