# 本地 PostgreSQL 运行时切换进度

用户目标是让本地库日常使用 PostgreSQL。当前**尚未切换生产应用**；旧 JSON 仍是普通启动的权威数据，不能删除。

## 已完成的下一步

- `PostgresLibraryIndexStore` 可以在已导入的隔离数据库中读取索引和写入索引。
- 保存使用原迁移标记中的 SHA-256 作为预期版本。其他操作已写入时，旧快照保存被拒；索引条目、文件夹和版本标记在同一事务中提交或回滚。
- 大批量条目通过临时表和二进制 COPY 传入，更新与删除在数据库内完成；不逐行往返。
- `--self-test-postgres` 新增读写、旧版本拒绝及资料表不受索引保存影响的检查。
- `PostgresLibraryMetadataStore` 也支持作品资料的事务读写、版本冲突拒绝；索引更新和资料更新彼此不覆盖。

隔离 PostgreSQL 18.6：1 部视频 / 1 条资料，以及 3000 部视频 / 100 条资料 / 10 个文件夹，两组均通过；索引与资料均完成读写和过期版本拒绝，源 JSON 字节不变。测试集群已停止，未读取真实视频库。

另用 30,000 部合成视频 / 12 个文件夹完成同一导入、完整回读、更新、旧版本拒绝与源文件不变检查，进程总耗时约 6.9 秒。这是离屏合成库结果，不代表真实海报、磁盘扫描或界面帧率。

索引保存还验证了文件改名路径：先删除旧 ID，再插入新 ID，同一事务提交；旧路径不残留。

## 切换前必须补齐

1. 配置、资料、审核事务与历史、人物、标签、评分、队列、备份恢复等仍有独立 JSON 写入入口。不能只把视频索引切到数据库，否则状态会分裂。
2. 将所有相关读写入口改用同一 PostgreSQL 存储层，审核/撤销/恢复保持原子性，并在 3 万部合成库验证性能。
3. 为普通 Windows 用户提供可安装、可升级和可恢复的本机 PostgreSQL 服务；仅监听 loopback，凭据存 Windows 凭据管理器。迁移前备份真实库，导入后逐项核对再切换模式。

当前新增存储层只由显式隔离自检调用，**不会改变正常启动**。
