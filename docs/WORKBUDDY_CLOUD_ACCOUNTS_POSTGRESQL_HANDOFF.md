## 目标

实现可独立部署的账号与错误日志接收服务。Windows 客户端登录后方可上传**错误日志**；服务器 PostgreSQL 保存邀请、账号、会话、上传审计与日志元数据。视频路径、封面、文件名、API Key、完整配置、视频库索引和媒体文件均不得上传。云端数据库与每个用户本机视频库是两个独立系统，不做隐式同步。

## 安全与部署边界

- 仅提供 HTTPS API；当前 `yingvideo.top` 的公网解析与证书仍需核实。在域名未生效前可用 IP 加合适证书的测试环境，但不得让生产客户端使用明文 HTTP 或跳过证书校验。
- PostgreSQL 只监听服务端本机或私有网络；不得向公网开放 5432。应用使用最小权限数据库角色，不能用 `postgres` 超级用户连接。
- 邀请码一次性、有效期短、存哈希；账号密码使用成熟的密码哈希库及适当参数，不自行发明加密。会话令牌短寿命、可撤销、存哈希；加入登录与上传限速、请求大小上限、审计和错误返回。
- 客户端不得内置 SSH 私钥、服务器数据库密码、对称解密密钥或可逆“隐藏地址”。不要做“检测破解自动销毁”这类会误伤用户数据的行为。连接地址可公开，保护依赖 TLS、认证、授权和限速。
- 上传前在客户端预览并脱敏；用户明确点击上传后才发送。服务端再次校验只含允许的错误字段。保存日志时限定保留期，并给用户删除自己上传日志的能力。
- 不读取或修改真实视频库。若需要登录服务器 `43.226.58.187:43602`，先在隔离环境完成代码、测试与部署预案；服务器改动和数据库初始化过程必须可审计、可回滚。SSH 私钥仅用于操作者部署，不进入仓库、程序包或客户端。
