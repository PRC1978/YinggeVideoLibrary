# 流畅度、搜刮准确性与维护记录（2026-11-06）

## 已完成

- 修复分类图诊断对旧单列布局的依赖。两列布局下直接使用节点导航控件引用，600 部隔离库的完整分类图诊断恢复通过：540 个节点、188 条选中标签共现连线、23 页导航均可访问。
- 收紧无番号影视作品的自动批准：官方来源详情已核对、完整标题一致之外，还要求文件名含唯一明确年份，且详情年份一致。缺少年份、年份冲突或多个年份均留在人工审核。此变更可能增加待审数量，但可避免同名作品和翻拍被自动写错。
- 数据库主版本不匹配时明确显示库文件版本和安全迁移提示；现有版本检测仍在启动前拒绝使用不匹配的数据库，不会重新初始化或覆盖资料。

## 流畅度对照

同一隔离夹具：600 部视频、540 个图节点、188 条所选标签连线。对分类图“将多次线段绘制合为一个向量几何”的改动做交替 A/B：基线旋转帧平均 27.7、28.7 ms；候选 27.1、28.7 ms。差异不足以证明稳定提速，因此撤回该绘制改动。最终原绘制路径诊断旋转帧平均 28.8 ms、P95 32.6 ms；完整节点和连线保持可见、可访问。

这说明当前瓶颈不能靠合并绘制调用解决。下一步需要在同一夹具上分别量出 540 节点投影、点绘制、标签避碰、软件光栅化的耗时，再选择有证据的改法；目标是降低交互帧耗时，不能以删节点、删连线或删交互换数字。

## 后续维护顺序

1. 建立经人工核对的混合来源样本集，记录“自动通过、待审、误配、漏配”的分母与原因；以误配率为首要指标。
2. 分类图做分阶段耗时采样后优化，保留节点、连线、旋转和缩放；每项优化都要同夹具交替复测。
3. PostgreSQL 主版本升级先设计“旧运行时导出并校验备份 → 新运行时导入 → 回滚”的端到端流程，再升级打包版本；不能仅替换运行时文件。
